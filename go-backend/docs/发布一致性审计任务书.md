# LessonForge 发布一致性审计任务书

## 1. 审计 Goal

在不修改源码、数据库、Docker Compose、镜像和运行中容器的前提下，确认当前 LessonForge 环境是否具备可发布、可验收的条件，并建立以下四者的可追溯对应关系：

```text
磁盘源码版本 → Docker 镜像版本 → 数据库 migration 版本 → 运行配置/外部服务版本
```

最终必须给出一个明确结论：`READY`、`NOT_READY` 或 `BLOCKED`，不能只描述现象。

## 2. 主问题

必须回答：

1. 当前磁盘源码、运行镜像和运行容器是否来自同一版本？
2. 数据库实际 migration 是否与当前源码要求一致，特别是 011 和 012？
3. 当前 Compose、容器环境变量和实际运行配置是否一致？
4. Model、Parser、RAG、模板能力服务和 PPT Engine 是否真实可达？
5. `/healthz` 检查的是存活还是就绪？数据库、队列、共享存储和外部服务是否被覆盖？
6. `LockedSpecification → GenerationJob → PPT Engine → Artifact` 是否存在真实生产闭环？
7. 历史 `READY` Artifact 是否都有物理文件，并且文件大小和 SHA-256 一致？

## 3. 审计范围

### 3.1 源码

检查：

- `D:\pri_work\LessonForge-go-backend`
- `cmd/lessonforge-server/main.go`
- `internal/platform/config`
- `internal/platform/database`
- `internal/platform/httpapi`
- `internal/generation`
- `internal/pptengine`
- `internal/templatebinding`
- `migrations/`

重点确认源码实际查询、写入和依赖的数据库字段，以及 GenerationJob 的生产创建入口。

### 3.2 Docker 和运行环境

检查：

- 当前运行中的容器名称、镜像名称、镜像 digest、创建时间、启动时间
- 容器内源码或二进制的版本指纹
- Compose 文件、实际环境变量、网络和 volume
- `LESSONFORGE_ENABLE_GENERATION_WORKER`
- `LESSONFORGE_PPT_ENGINE_BASE_URL`
- RAG、Parser、模板能力相关地址

### 3.3 数据库

检查：

- `schema_migrations` 当前最大版本
- `model_connections` 实际列结构
- `provider`、`capabilities`、`capability_verification` 等字段
- `generation_jobs` 的历史状态
- `artifacts` 与 `file_objects` 的物理文件对应关系

禁止输出 API key、Bearer token、加密密文和其他敏感值。

### 3.4 外部能力

只检查可达性、版本和健康状态，不修改外部服务：

- Model
- Parser
- RAG
- Template Capability/Profile
- PPT Engine
- 共享 artifact volume

## 4. 证据规则

每项结论必须标记为以下之一：

- `VERIFIED`：当前现场有直接证据
- `MISMATCH`：两个运行边界存在明确不一致
- `NOT_VERIFIED`：当前没有足够证据
- `BLOCKED`：因服务、权限、网络或工具缺失无法验证
- `HISTORICAL_ONLY`：只有历史文档或历史记录，不能证明当前状态

不得用以下内容替代现场证据：

- 历史工作报告
- README 声明
- 单元测试通过
- `/healthz` 返回 200
- 镜像名称相同但未核对 digest
- 数据库表存在但未核对 migration 版本

## 5. 禁止事项

本任务为只读审计，禁止：

- 修改源码
- 执行 migration
- 重启、删除或替换容器
- 修改 Compose、环境变量、网络或 volume
- 删除、修复或重建 Artifact
- 发送真实模型请求或产生外部业务副作用
- 打印任何密钥、token、密码或完整连接串

如果必须执行具有写入风险的动作才能验证，标记为 `BLOCKED`，不要自行执行。

## 6. 必须交付的文档

输出一份现场审计报告，至少包含：

1. 结论摘要：`READY`、`NOT_READY` 或 `BLOCKED`
2. 源码/镜像/数据库/配置版本矩阵
3. 数据库 migration 和关键字段核对表
4. Docker 容器、网络、volume 和外部服务拓扑
5. Generation 生产创建入口和真实调用链
6. `/healthz` 与 readiness 覆盖差异
7. Artifact 物理文件一致性统计
8. P0/P1/P2 问题清单
9. 每个问题的建议负责人
10. 已验证、未验证、阻塞项分开列出

每个关键结论都要附：

```text
检查项 | 实际值 | 证据来源 | 当前状态 | 影响 | 建议负责人
```

## 7. 完成标准

只有在以下条件全部满足时，才能报告 `READY`：

- 源码、镜像和数据库 migration 可追溯到同一发布版本
- 011/012 migration 与源码字段一致
- 所有必需外部服务真实可达
- GenerationJob 的生产创建入口明确
- 至少完成一次真实 Generation 闭环
- PPTX Artifact 文件存在且大小、SHA-256、数据库记录一致
- readiness 能反映数据库、队列、共享存储和关键外部服务状态

否则必须报告 `NOT_READY` 或 `BLOCKED`，不得使用“基本可用”替代最终状态。
