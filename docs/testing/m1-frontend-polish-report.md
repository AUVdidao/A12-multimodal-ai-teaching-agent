# A12 M1 演示级前端视觉与体验优化验收报告

更新时间：2026-07-11  
基线提交：`3a3305a5a39ae55b6de531bab974388aa25d8483`  
工作分支：`m1-frontend-demo-polish`

## 1. 任务目标

在不修改后端接口、数据库模型和 M1 业务规则的前提下，将已完成的需求澄清闭环从工程页面提升为适合比赛答辩演示的教育科技 SaaS 原型。优化范围覆盖应用壳层、M1 步骤导航、项目入口、需求表单、AI 澄清对话、摘要确认、响应式布局和完整交互状态。

## 2. 优化前主要问题

- 全局样式集中在单一 CSS 文件，缺少颜色、间距、圆角、阴影和控件高度变量。
- 首页偏工程入口，直接突出接口检查，产品价值和完整 M1 路径不清楚。
- 左侧导航将未实现的 M2 页面与当前能力并列，容易造成能力已开放的误解。
- 项目列表、生成模式和表单页面的标题区、卡片、状态样式不统一。
- 教学需求与 AI 澄清混在长表单中，缺失字段、追问和对话记录不够突出。
- 摘要页缺少正式确认单语义，草稿、已确认及下一阶段边界不够醒目。
- loading、empty、error、success、disabled 与重复提交防护分散在各页面。
- 1366px 下信息密度和主次关系不足，1920px 下内容容易显得松散；窄屏步骤导航曾存在内部横向滚动。

## 3. 视觉规范

- 主视觉：浅色、专业、克制的教育科技 SaaS；避免霓虹、玻璃拟态和无意义装饰。
- 颜色：蓝色主操作、青绿色成功、琥珀色待处理/警告、紫色 AI 辅助标识，辅以中性文字与边框。
- 布局：主内容最大宽度 `1180px`，固定桌面侧栏，1024px 以下切换为抽屉导航。
- 圆角：卡片不超过 `8px`；阴影只用于需要层级的容器，并保持低对比。
- 动画：页面淡入和卡片轻微位移均低于 300ms；支持 `prefers-reduced-motion`。
- 图标：统一复用现有 `@element-plus/icons-vue`，不使用 emoji 代替菜单或状态图标。

设计变量位于：

- `frontend/src/styles/tokens.css`
- `frontend/src/styles/base.css`
- `frontend/src/styles/components.css`

## 5. 页面优化

### 首页

展示产品名称、M1 价值、5 步演示路径、真实项目数量、最近项目和服务状态。主入口为“新建教学项目”和“查看全部项目”；未将资料上传或内容生成描述为可用能力。

### 项目列表

使用响应式卡片展示教师可理解的状态、课程、章节、授课对象、模式和更新时间；补齐加载、空、错误、重试状态，并根据项目状态进入安全业务节点。

### 新建项目

按课程信息和项目说明分区，补充简短字段提示、创建价值说明、提交 loading 和防重复提交；成功后自然进入模式选择，API 字段不变。

### 生成模式

模式从后端加载并使用等高选择卡展示名称、说明和适用场景；已保存模式刷新后回显，下一步按钮具备 loading 和 disabled 状态。

### 教学需求与 AI 澄清

桌面端采用“需求表单 + AI 澄清侧栏”，窄屏自动单列。表单分为课程基础、教学设计、输出偏好和自由描述；最近需求版本、保存反馈和错误提示均可见。AI 侧栏展示缺失字段、问题气泡、补充控件、完整性状态和对话历史，消息区限制高度并自动滚动。所有原有 requirement、clarification、dialogue 接口、`sessionId` 和 `roundNo` 规则保持不变。

### 摘要确认

重构为正式“教学需求确认单”，主区展示结构化内容，侧栏展示来源需求版本、生成模式、更新时间和确认时间。草稿可编辑，确认前二次确认，确认后字段锁定；刷新后仍为已确认。下一阶段只显示“资料上传与知识库构建”，并明确标记 M2 尚未实现。

### 应用壳层

统一顶部品牌、Mock AI 状态、侧栏分组和路由选中态。当前项目编号始终可见；M2 导航禁用并带锁定语义。页面标题随路由更新，桌面与移动布局切换稳定。

## 6. M1 步骤判断与状态安全

- 创建项目：新建页为当前步骤；已有项目可安全返回。
- 生成模式：项目创建后解锁，模式来自后端并可刷新恢复。
- 教学需求：模式页完成后解锁，以 latest requirement 判断是否已保存。
- AI 澄清：以 clarification 完整性和缺失字段判断当前/完成状态。
- 摘要确认：仅需求完整后解锁，以 summary 的 `DRAFT` / `CONFIRMED` 状态判断。
- 未解锁步骤使用 disabled，不允许通过步骤条跳过业务约束。
- 页面刷新重新读取后端状态，不用纯前端假状态推断完成度。

## 7. 交互状态与可用性

- 所有 API 主操作具备 loading、disabled、成功和失败反馈。
- 表单提交期间禁止重复点击；补充澄清和摘要确认同样有防重复提交。
- 错误信息转换为用户可理解文案，不暴露 Java 异常类、堆栈或 Axios 对象。
- 输入框保留可见 label，placeholder 只作示例；图标按钮具备 `title` 或 `aria-label`。
- 状态不仅依赖颜色，同时使用文字、图标和 disabled 语义。
- 真实浏览器键盘焦点、按钮和表单控件可访问；移动抽屉有明确开关。

1. 首页和项目列表；
2. 新建项目 `#17`（高中信息技术 / 人工智能与机器学习入门）；
3. 保存生成模式；
4. 保存不完整需求；

9. 保存并二次确认；

11. 返回需求澄清页，路由和历史状态恢复正常。
